# BP 打磨舱 · 双创赛事商业计划书诊断平台

> 上传 BP，5 分钟内出**清单式诊断报告**：风险 ≤ 10 条、按严重度排序、每条必带一条今天能做的补救动作。

## 1. 这是什么

面向「互联网+」「挑战杯」等双创赛事团队的**商业计划书打磨工具**。它做的是一件很窄的事：**只做逻辑校验，不做代写，不做夸奖。**

具体拆成五个模块：

| # | 模块 | 作用 |
|---|---|---|
| 01 | BP 十二页结构模板 | 12 页 × 每页 3 道必答题，按 P0/P1/P2 排优先级 |
| 02 | 评委视角 30 问挑战库 | 5 维度 × 6 问，按命中要点数判定过/存疑/未答到点 |
| 03 | 路演稿生成与三档裁剪 | 按 240 字/分钟裁出 5 / 8 / 15 分钟三档 |
| 04 | 毒舌评委 · 三轮答辩模拟 | 前 2 轮追问，第 3 轮给示范应答并要求改写 |
| 05 | 上传 BP · 输出诊断报告 | 本机解析 PDF/PPTX/TXT/MD，出清单式报告 |

### 当前版本的性质

- 单文件纯前端，双击 `index.html` 即可运行，**不含任何外部网络请求**；
- 12 页答案、30 问作答、路演稿与诊断记录保存在浏览器 **localStorage** 中；
- 上传的 BP **在本机解析，不传服务器**；原型内置一份「刻意写得空泛」的示例 BP 用于演示诊断口径；
- 判定与打分以**规则逻辑**运行（可复现：同一份 BP、同一参数，两次诊断结果一致），未调用外部模型服务。

## 4. 功能模块详解

### 01 BP 十二页结构模板

- **骨架**：封面定位 / 痛点验证 / 方案形态 / 技术壁垒 / 市场测算 / 商业模式 / 竞品差异 / 落地进展 / 团队分工 / 财务融资 / 社会价值 / 风险里程碑。
- **规则**：每页只问 3 题，且必须问「**数字从哪来、谁验证的、不成立时怎么办**」；空页不进路演稿、不进诊断。
- **优先级与裁剪**：

  | 优先级 | 页面 | 出现档位 |
  |---|---|---|
  | P0 | 封面、痛点、方案、技术、商业模式、进展 | 5 分钟档必留 |
  | P1 | 其余 | 8 分钟档 |
  | P2 | 其余 | 仅 15 分钟档 |

- **界面**：左侧 12 页列表（显示 n/3 完成度），右侧该页三问编辑区 + 上/下页 + 导出 Markdown。
- **输出字段**：页码 / 标题 / 优先级 / 三问 / 我的答案 / 完成度。
- **验收**：36 格全部有内容，路演稿生成率 100%；未填页在稿中直接缺席并被列出。

### 02 评委视角 30 问挑战库

- **规则**：5 维度（技术可行性 / 市场规模 / 商业模式 / 团队结构 / 社会价值）× 6 问；每题预设 3 个必答要点，按命中数判定：**≥2 过、1 存疑、0 未答到点**。
- **反馈固定三段**：①命中（引用其原词）②缺口（缺哪个要点）③一句更狠的追问 + 一条今天能做的动作。
- **界面**：维度标签（带 0–12 得分）+ 题卡（要点提示 / ≤120 字作答 / 判定徽章 / 反馈块）。
- **输出字段**：维度 / 题号 / 问题 / 作答 / 命中要点 / 缺口要点 / 判定 / 补救动作。
- **验收**：30 题判定**可复现**；判定结论必带一条动作；无一处出现「很好 / 不错 / 有想法」。

### 03 路演稿生成与三档裁剪

- **规则**：按 240 字/分钟折算三档字数 —— **5 分钟 1200 字 / 8 分钟 1920 字 / 15 分钟 3600 字**；只搬运用户写的事实，**不新增任何数据与案例**。
- **降级策略**：5 分钟只留 P0、8 分钟留 P0+P1、15 分钟全留；每页给建议秒数与字数，超出上限时按字数从多到少列出删除顺序。
- **界面**：三档卡片（含字数上限）+ 倒计时器 + 逐页稿 + 超时提示。
- **验收**：三档切换 ≤ 0.2s；字数误差 ≤ 5%；5 分钟档只含 P0 页；超时项**必须显式标出**。

### 04 毒舌评委 · 三轮答辩模拟（迭代版）★

- **第 1 轮**：从 30 问中挑最弱的一题，只问，不点评。
- **第 2 轮**：抓住第 1 轮答案里的一个数字或形容词往下追（谁给的 / 什么口径 / 换个数还成立吗）。
- **第 3 轮（迭代点）**：**不再提问**，改为给一段四段式示范应答 ——

  1. **结论**（一句话不铺垫）
  2. **证据**（来源 + 时间 + 口径 + 样本量）
  3. **边界**（什么条件下不成立）
  4. **下一步**（30 天动作 + 验收指标）

  要求团队按此骨架**改写自己的版本**；收到改写后只做四项对照（结论是否前置 / 证据是否带出处 / 是否承认边界 / 是否有收口动作），逐项标有或无，不打分、不评价文笔、不代写内容。
- **验收**：第 3 轮必须出现示范应答，且示范中的数字一律为 **XX 占位**（不提供可抄的假数据）；对照恒为 4 项；三轮记录可导出。

### 05 上传 BP · 输出诊断报告

- **流程**：拖拽上传 PDF / PPTX / TXT / MD（**本机解析，不上传服务器**），粘贴兜底；按 5 维度扫规则，出清单式报告。
- **输出恒为 6 字段**：评审维度 / 评分 1–5 / 风险项 / 证据（BP 原文）/ 补救动作 / 再评估标准。
- **排序**：风险项总数 ≤ 10，按维度保底配额后按 **P0 阻断 / P1 重要 / P2 提示**排序。
- **证据口径**：每条证据必须是从 BP 原文截取的 **≤ 26 字**片段，前后加省略号，**不改写、不概括**；缺失型风险写「全文未出现……」并指出缺哪几项。
- **动作口径**：每条补救动作必须以动词开头（删掉 / 改写成 / 补上 / 填成），且可在当天或 30 天内完成。
- **市场测算**：提供 4 参数自算台（可触达用户数 × 渗透率 × 客单价 × 年频次），**缺一不出结果**，工具不设默认值。
- **验收**：出报告 ≤ 5 分钟（原型实测秒级）；改完任一条后重新上传，该条须从清单消失；同一份 BP 同一参数两次诊断结果一致。

## 5. 诊断报告样例（节选）

以下为对一份**刻意写得空泛**的示例 BP 的输出，用于展示字段口径：

**市场规模测算 ｜评分 1/5**
- **风险项**：有数字无性质说明；引「据统计」无报告名；缺自下而上测算路径。
- **证据**：「市场规模有望达到千亿级别……据统计，未来几年将保持高速增长。」
- **补救动作**：删掉千亿与「据统计」，改填四参数：可触达用户数 × 渗透率 × 客单价 × 年频次，各注明来源；算不出就先写「暂未测算，X 月前完成 30 份用户访谈」。
- **再评估标准**：BP 中出现可复算的测算式，四参数均有出处，且与自算 SOM 偏差 ≤ 3 倍。

完整五维度样例见 `docs/BP打磨舱_诊断报告清单.md`。

## 7. 硬约束（设计红线）

1. **禁止吹捧式反馈** —— 不出现「前景广阔」「团队优秀」「很有潜力」，只输出风险、证据、动作；
2. **禁止虚构市场数据与引用** —— 所有规模、增长率、渗透率必须用户自填参数后由公式算出，工具不设默认值、不引用行业报告；
3. **不得承诺获奖概率** —— 不做获奖率、晋级率、评分预测，只做逻辑校验与表达打磨。

## 9. 已知限制

- 原型未接入模型服务，判定与打分以规则逻辑运行（好处是可复现）；
- PDF / PPTX 解析覆盖常见文本型文件，扫描件与复杂版式可能抽取不全；
- 无团队协同，多人共用一台设备。
